# /update-docs — 문서 일괄 갱신

당신(메인 AI)은 최근 작업 내용을 바탕으로 `docs/context.md`, `docs/tasks.md`, (필요 시) `docs/plan.md` 를 갱신한다.

**언제 쓰나**:
- 긴 작업 세션 끝날 때 (컨텍스트 날아가기 전 스냅샷 기록)
- 주요 결정 내린 직후 (ADR 추가)
- 커밋/PR 직전 (문서와 코드 동기화)
- `/project-status` 에서 "문서 오래됨" 경고 받았을 때

---

## 이 커맨드만의 규칙

> 말투, 승인 절차 같은 공통 규칙은 `CLAUDE.md` 의 공통 작업 규칙을 따른다.

1. **제안은 구체적으로.** 어느 문서의 어느 절을, 지금 무엇이 적혀 있고, 무엇으로 바꿀지 셋을 함께 준다.
2. **기존 ADR 을 덮어쓰지 않는다.** 추가만 한다.
3. **회고형 일괄 갱신용이다.** 결정 한 건을 즉시 남기려면 `/decision` 이 낫다.

---

## Phase 0: 선행 체크

1. `docs/plan.md`, `docs/context.md`, `docs/tasks.md` 존재 확인.
2. `.git` 있으면 git 활동 기반 자동 추정 활용.

---

## Phase 1: 변경사항 / 맥락 수집

다음 소스로부터 "마지막 갱신 후 무슨 일이 있었는지" 추정:

### 소스 1: git 활동

`docs/context.md` 가 마지막으로 커밋된 시점을 기준으로 삼는다. 문서에 적힌 날짜 필드가 아니라 git 이 아는 실제 시각이다.

```bash
SINCE=$(git log -1 --format=%cd --date=short -- docs/context.md)
git log --oneline --since="$SINCE"
git diff --stat HEAD~$(git rev-list --count --since="$SINCE" HEAD)..HEAD
```

문서가 한 번도 커밋되지 않았으면 최근 10커밋(`git log --oneline -10`)으로 대체한다.
최근 수정 파일 목록 / 커밋 메시지에서 주요 변경 식별.

### 소스 2: 현재 대화 맥락
이 세션에서 수행한 작업 요약 (사용자 요청, 에이전트 호출, 수정한 파일 등).

### 소스 3: 기존 문서
- `docs/context.md` Implementation Snapshot 섹션 — 이전 스냅샷과 비교
- `docs/tasks.md` — 진행 중 ⏳ / 미완료 항목 중 최근 완료 가능한 것 식별

### 소스 4: 활성 기능
- `docs/features/*/tech-spec.md` 최근 수정 시점 확인

## Phase 2: 갱신 제안 생성

3개 영역에 대해 각각 제안:

### 2-A. context.md — Implementation Snapshot

현재 `## 현재 구현 스냅샷` 섹션을 **최신 정보로 전면 교체**.

제안 내용:
- **마지막 업데이트 시점**: <현재 YYYY-MM-DD HH:MM>
- **현재 구현 중인 것**: <대화 맥락 + git 활동 기반>
- **최근 세션에서 내린 주요 결정**: <있으면 목록>
- **최근 수정된 주요 파일**:
  - `경로/파일.ext` — <왜 수정했나>
- **현재 블로커**: <있으면>
- **다음 즉시 해야 할 일**: <tasks.md 기반 추정>
- **미완성/미커밋 변경사항**: <git status 기반>

> **압축 원칙** (`context-template.md` 참조):
> - 시도 1차/2차/3차 단계별 실패 스토리 ❌ → 결론만 한 줄로
> - 측정 raw (토큰 수, 시간 ms) ❌ → 핵심 효과 (-17%, -67%) 만, raw 는 측정 로그
> - 함수명/파일 경로 나열 ❌ → "수정된 주요 파일" 항목에 1줄씩만
>
> 자기 검열: "이 디테일이 1주일 후에도 가치 있는가? 코드 보면 알 수 있는 건 빼자."

### 2-B. context.md — ADR 추가 제안 (선택)

세션 중 **새로운 결정**이 있었으면 ADR 추가 제안. 양식은 `/decision` 커맨드 표준과 동일:

```
### [날짜] [태그들] 결정: <요약>
- 상황:
- 선택:
- 이유:
  - ...
- 대안과 거절:
  - <후보>: <이유>
- 영향:
- 관련:
```

각 결정마다 사용자에게 **"이거 ADR로 추가할까요?"** 개별 확인.

**분업 규칙**:
- 결정 **1건** 에 집중하고 싶으면 → `/decision` 단독 실행이 더 빠르고 품질 높음.
- `/update-docs` 는 **여러 ADR + Snapshot + tasks 일괄** 회고형 플로우.
- 즉 회고 중 ADR 누락 감지 → 여기서 추가. 실시간 단건 → `/decision`.

**ADR 압축 가이드** (`context-template.md` 참조):
- ❌ 시도 1차 → 결과 → 시도 2차 → 결과 ... 단계별 스토리 → ✅ 결론만 한 줄로 ("초기 X 시도, Y로 보완 후 채택")
- ❌ 측정 raw (input 12,234 tokens, output 4,521, ...) → ✅ 핵심 효과 (-67% 비용, 시간은 미달) 만
- ❌ 함수명·파일 경로 나열 → ✅ "API 시그니처 변경" 정도. 큰 후속 작업은 tasks.md 항목으로 분리

핵심: "디테일이 필요하면 커밋·코드·측정 로그에서 찾는 게 정상 흐름. ADR 은 의사결정 + 인덱스."

### 2-C. tasks.md — 체크오프 + 새 작업 추가

- **완료 감지**: 진행 중 ⏳ 항목 중 대화/커밋 근거로 완료된 것 찾아 ✅ 처리 제안
- **개별 todo**: `[x]` 체크오프, **원래 위치 유지** (이동 X)
- **기능 전체 완료 감지** 시: `tasks-template.md` 의 "완료된 기능" 섹션 표준 압축 패턴으로 이동 제안 (한 줄 요약 + 단계 + 커밋 해시 + 코멘트)
- **새로 생긴 작업**: 대화 중 나온 할 일, 리뷰 이슈 등 추가 제안
- **블로커 업데이트**

### 2-C2. milestones.md — 기능 상태 반영

완료된 기능이 있으면 `docs/milestones.md` 의 포함 기능 표에서 상태를 갱신한다. 마일스톤 전체가 끝났으면 완료 판정 기준을 충족했는지 확인하고 실제 완료일을 적을지 묻는다.

### 2-D. plan.md — 보통 X, 필요 시만

`plan.md` 는 큰 방향 변경 시에만 수정. 다음 경우만 제안:
- 프로덕트 방향 변경 감지
- Phase 완료 / 다음 Phase 진입
- 새 리스크 발견
- MVP 정의 변경

일반적으론 **"plan.md 변경 제안 없음"** 으로 표시.

## Phase 3: 사용자 확인 + 반영

제안을 다음 형식으로 사용자에게 제시:

```markdown
# 📝 Update Proposal — <YYYY-MM-DD HH:MM>

## 1. context.md — Implementation Snapshot 갱신

(Before / After 비교 또는 제안 전문)

**반영?** Y / N / 수정

## 2. context.md — 새 ADR 추가 (N개)

### ADR 1: [태그] <제목>
(제안 전문)
**반영?** Y / N / 수정

### ADR 2: ...

## 3. tasks.md — 변경사항

### 완료 처리 제안 (N개)
- [x] <작업> — 근거: <커밋 / 대화 내용>

### 새 작업 추가 제안 (N개)
- [ ] <작업> [Effort] — 출처: <대화 / 리뷰 이슈>

### 블로커 변경
- <변경 사항>

**반영?** Y / N / 항목별 선택

## 4. plan.md — 변경 제안

<없음 or 구체 제안>
```

### 사용자 응답 처리

- **"Y" / "전부 반영"**: 모든 제안을 해당 파일에 실제 반영
- **"N" / "나중에"**: 반영 없이 종료
- **"1, 3만"** 또는 선택적**: 선택된 것만 반영
- **"수정 후 반영"**: 사용자 수정 요청 반영 후 반영

반영한 내용은 커밋으로 남긴다. 문서에 날짜 필드를 손으로 적지 않는다. 신선도는 git 이 판정한다.

---

## Phase 4: 반영 후 확인

반영 완료 후 사용자에게 간단 보고:

```
✅ 문서 갱신 완료

- context.md: Implementation Snapshot 갱신 / ADR N개 추가
- tasks.md: N개 완료 처리 / M개 추가
- plan.md: 변경 없음

다음: /project-status 로 갱신 상태 확인 / 계속 작업
```

## 실패 시나리오

| 상황 | 대응 |
|---|---|
| context.md/tasks.md 없음 | `/kickoff` 먼저 필요 안내 |
| 제안할 변경 없음 | "문서가 최신입니다. 갱신할 것이 없습니다." 보고 |
| 대화 맥락 부족 | 사용자에게 "이번 세션에 주요 변경 있었나요?" 질문 |
| 충돌하는 결정 감지 | "기존 ADR과 충돌: <기존 결정>. 폐기/수정/공존 중 선택" 요청 |
| git log 접근 불가 | 대화 맥락만으로 제안 |
